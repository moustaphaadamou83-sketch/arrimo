## 2. Pourquoi la base de test ne peut pas être créée

Constats reproduits sans SQL modificatif :

| Contrôle | Observation | Conséquence |
|---|---|---|
| Identité | UID 0, mais `CapEff=0`, `CapBnd=0` | L'identité root n'accorde pas ici les capacités de changement de groupe/utilisateur |
| Protections | `NoNewPrivs=1`, `Seccomp=2` | L'environnement est restreint ; ces valeurs ne permettent pas à elles seules de nommer la règle exacte qui filtre chaque appel |
| `runuser -u postgres -- id -u` | `cannot set groups: Operation not permitted` | L'échec précède `createdb`, l'authentification PostgreSQL et les migrations ; changer le mot de passe ne le résout pas |
| Socket PostgreSQL local | Connexion refusée avec `EPERM` | Impossible également d'utiliser ce transport directement |
| Écoute `127.0.0.1`, port éphémère | `EPERM` | Les serveurs HTTP des tests API et navigateur ne pourraient pas démarrer |

La cause immédiate du premier refus est le changement de groupes requis par `runuser`, non autorisé dans ce processus sans capacités effectives. Les deux autres refus établissent des restrictions de transport supplémentaires. Le profil du conteneur n'étant pas disponible, on ne prétend pas attribuer chaque refus à une règle seccomp particulière.

**La restriction système n'a pas été levée et n'est pas réparable depuis cette session sans changer son cadre de sécurité.** Aucun `chmod`, `setcap`, changement de groupe, modification de `pg_hba.conf`, élargissement de rôle, désactivation de protection ou ouverture réseau n'a été tenté.

Correction apportée au lanceur : diagnostic avant lecture de la configuration et avant toute création de base ; sortie 2 et rapport `bloque_prerequis_systeme`, plutôt qu'une exception sans bilan. Le diagnostic est aussi exécutable séparément :

```bash
cd /root/arrimo-sh-erp
/opt/arrimo-runtime/node-v24.22.1/bin/node scripts/diagnostic-recette-sh.cjs
```

Il ne lance aucun SQL. Son succès système ne certifierait pas les droits SQL, les migrations ou Chromium.

## 6. Isolation : ce qui est prouvé et ce qui manque

La migration SH 10 crée des affectations globales/pays/client/hôpital/projet, des fonctions de périmètre, des politiques RLS et emploie un rôle PostgreSQL `*_scope` sans contournement RLS. `perimetre-pool.js` positionne l'identité et le mode lecture/écriture dans chaque transaction. Les routes API ajoutent les droits par fonction et rôle personnalisé.

La suite accès contient déjà un scénario Canada/Togo, deux projets d'un même hôpital, refus de lecture d'un projet voisin, export refusé et refus d'auto-attribution globale en SQL. **Ce test n'a pas été exécuté dans cette mission.** Il utilise une affectation à un projet ; il faut en plus tester explicitement les affectations de type pays/client/hôpital, toutes les mutations et les chemins indirects (PDF, documents, notifications, journal, rapports, OG).

L'isolation SH n'établit pas à elle seule que les vues Réseau/National et transferts d'Arrimo restreignent les communications à un réseau international autorisé. Cette exigence nécessite des scénarios négatifs multi-pays dans Arrimo, distincts de ceux de SH. Aucun succès global d'isolation entre pays n'est affirmé ici.

## 7. Anomalies et risques de déploiement

**Bloquants avant pilote :**

- Environnement incapable de créer les fixtures et d'écouter en HTTP ; aucune recette intégrée actuelle.
- Migration SH 10 non revalidée. Elle exige un rôle `owner_scope` déjà préparé ; le lanceur actuel ne le provisionne pas. Ne pas exécuter le préparateur de rôles publics pour un test : préparer ce prérequis dans le seul cluster de recette dédié.
- `db/sh-vider.js` supprime les tables mais ne retire pas les fonctions `sh_scope_*`. La recette UI remet SH à zéro à chaque largeur ; la seconde initialisation risque donc d'échouer sur `CREATE FUNCTION sh_scope_uid`. Anomalie d'inspection à reproduire sur PostgreSQL, pas erreur observée à l'exécution ici.
- Promotion incomplète des configurations et absence d'environnement pilote distinct.
- Critères de préparation à la mise en service incomplets ; le nouveau garde de tâches doit encore passer la recette réelle.
- Isolation complète, sauvegarde/restauration et reprise non prouvées sur la candidate.

**Autres écarts à terminer :** portail client support, cycle de vie des projets, fonctions ERP détaillées, référentiel international/devise automatique, recette SQL du pipeline multidevises corrigé, tests réels du vocal et contrôle des fournisseurs externes. Les paramètres fiscaux et contractuels existants restent à faire valider par les responsables concernés ; cet audit n'en confirme pas l'exactitude.

Le dossier contient de nombreux fichiers non commités. Une publication doit porter sur une candidate figée avec manifeste, pas simplement le commit HEAD ni une copie improvisée du répertoire. Aucun déploiement n'est autorisé par ce rapport.
